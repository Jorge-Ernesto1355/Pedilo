# Visual QA

You are the final design reviewer.

Do not assume the implementation is good simply because it works.

## Review objectively

Inspect the final implementation as if you were an external design director seeing the website for the first time.

## Visual checklist

### Brand

* Does it feel like Pedilo?
* Does it have a recognizable personality?
* Does it communicate commerce and entrepreneurship?
* Does it look intentional?

### AI appearance

Ask:

* Does it look AI-generated?
* Does it look like a SaaS template?
* Are there too many cards?
* Are there too many rounded elements?
* Are there unnecessary gradients?
* Is there excessive blur?
* Are there unnecessary icons?
* Are there unnecessary animations?
* Does the page feel predictable?

### Typography

Check:

* Hierarchy
* Font sizes
* Line height
* Weight
* Width
* Contrast
* Consistency

### Layout

Check:

* Alignment
* Container width
* Spacing
* Section rhythm
* Visual balance
* Empty space
* Density

### Components

Check:

* Buttons
* Cards
* Navigation
* Forms
* Inputs
* Links
* Icons

### Content

Check:

* Clarity
* Grammar
* Repetition
* Generic wording
* CTA clarity
* Marketing claims

Never introduce fabricated claims during QA.

### Responsive

Review:

* Mobile
* Tablet
* Desktop
* Large desktop

Look specifically for:

* Overflow
* Broken layouts
* Unreadable text
* Excessive whitespace
* Crowded sections
* Misaligned elements
* Broken images

### Accessibility

Check:

* Contrast
* Focus states
* Semantic HTML
* Keyboard navigation
* Alt text
* Reduced motion

## Brutal review

Ask:

"If I saw this website without knowing how it was made, would I believe a professional product team designed it?"

If the answer is no:

Identify why.

Then fix the highest-impact problems.

## Priority

Fix problems in this order:

1. Broken UX
2. Broken responsive behavior
3. Weak hierarchy
4. Inconsistent design system
5. Generic visual patterns
6. Typography
7. Spacing
8. Micro-interactions
9. Decorative details

Never spend time polishing decoration while structural problems remain.

## Final rule

Do not stop after finding problems.

When safe and appropriate, fix them directly and review the result again.
